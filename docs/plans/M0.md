## 3. Tailwind build, tema değişkenleri ve base.html

**Tailwind (öneri v4, açık soru 5):** `app/static/css/input.css`:
```css
@import "tailwindcss";
@source "../../templates";              /* sınıfları şablonlardan tara */
:root, .theme-light { --bg:#F6F7F9; --surface:#FFFFFF; --input:#FFFFFF; ... }   /* prototip .ak-root birebir */
.theme-dark { color-scheme:dark; --bg:#0B0F19; --input:#1E2638; ... }
@media (prefers-color-scheme: dark) { .theme-system { /* dark set */ } }
@theme inline { --color-bg: var(--bg); --color-surface: var(--surface); --color-input: var(--input); ... }
/* §6.0/5: input zemini var(--input), focus-visible halkası tüm etkileşimli öğelerde (checkbox/radio dahil) */
```
- Değişkenler prototipteki `.ak-root` setlerinden **birebir** kopyalanır (§14); sınıf adları SPEC §6.0'daki `theme-light/dark/system` olur (prototip `ak-*` kullanıyor, SPEC kazanır).
- `@theme inline` sayesinde şablonlarda `bg-surface text-text-2 border-border` yazılır; koyu tema `dark:` önekleriyle değil, değişkenlerin değişmesiyle olur.
- Komutlar: `scripts/build_css.sh` (tek seferlik, `--minify`) ve `scripts/build_css.sh --watch` (geliştirirken ikinci terminalde). Çıktı `app/static/css/app.css`, commit edilmez; Docker kendi içinde üretir.

**base.html:**
- `<html class="theme-{{ theme }}">` — `theme` sunucuda `theme` cookie'sinden okunur (`light|dark|system`, başka değer → `system`). Sınıf sunucuda basıldığı için sayfa yüklenirken renk yanıp sönmez (§6.0). `User` tablosu M1'de geldiği için M0'da cookie kullanılır; M4'te `User.theme`'e bağlanır (açık soru 1).
- Sol: logo (SVG, §14) + 4 link: Applications `/`, Learning, Documents, Settings; aktif olana `aria-current="page"`. Mobilde menü üstte/akordeon (Alpine ile aç-kapa).
- Üst bar: tema seçici (Light/Dark/System, Alpine: cookie yazar + `<html>` sınıfını değiştirir, sunucuya istek yok), zil (rozetsiz, statik), avatar menüsü (My profile, Settings, Sign out — M0'da pasif link).
- `{% block content %}`, sayfa sonunda toast bölgesi, `<script src="/static/js/...">` (CDN yok, inline script yok).
- M0'da **yok**: AI kredi kartı (M5), asistan butonu (M12a), zil paneli (M11) → açık soru 8.

**Bileşenler (Jinja macro, `templates/components/`):**
- `page_header(title, back_url=None, back_label=None)` → “← {back_label}” + başlık.
- `toast` → alt ortada `aria-live="polite"` bölge + Alpine store `toast.show(message, undo_url)`, 5 sn sonra kapanır; Undo butonu `hx-post` ile `undo_url`'e gider. **Sadece iskelet**; gerçek Undo altyapısı M4.
- `modal(id, title)` → native `<dialog>` (Esc ve odak yönetimi tarayıcıdan gelir, §14 erişilebilirlik).
- `drawer(id, title)` → sağdan açılan panel, `role="dialog" aria-modal="true"`, Esc ve dış tıklamayla kapanır.

> 🎓 **Jinja macro:** Şablon içinde parametre alan bir “fonksiyon”; aynı HTML'i her sayfada kopyalamak yerine `{{ page_header("Profile", back_url="/") }}` yazarsın. **CSS değişkeni (`--bg`):** Bir değeri tek yerde tanımlayıp her yerde `var(--bg)` ile kullanırsın; tema değişince sadece değişkenler değişir. **Cookie:** Tarayıcının her istekte sunucuya geri gönderdiği küçük anahtar-değer; böylece sunucu tema tercihini sayfayı oluştururken bilir. **HTMX / Alpine:** HTMX, HTML attribute'larıyla sunucuya istek atıp sayfanın bir parçasını değiştirir; Alpine, aç-kapa menü gibi küçük tarayıcı içi etkileşimler içindir.

## 4. config.py, db.py, main.py

- `config.py`: `Settings(BaseSettings)` — SPEC §11'deki tüm alanlar, tipli (`app_env: Literal["development","production"]`, `debug: bool`…), `.env`'den okunur. `model_validator`: `app_env == "production"` iken `SECRET_KEY` varsayılan/`< 32` karakter ya da `ENCRYPTION_KEY` boşsa **hata** (§11). `get_settings()` `lru_cache` ile.
- `db.py`: `create_engine(settings.database_url)`; SQLite ise `check_same_thread=False`. `get_session()` → `with Session(engine) as session: yield session` (FastAPI `Depends` ile).
- `main.py`: `FastAPI(debug=settings.debug)`, `/static` mount, `applications` router'ı. Tablo oluşturma **yok** (şema sadece Alembic ile).

> 🎓 **pydantic-settings:** Ortam değişkenlerini tipli bir Python nesnesine çevirir ve yanlış/eksik değeri uygulama açılırken yakalar. **Dependency (`Depends`):** FastAPI'nin bir fonksiyonun ihtiyaç duyduğu şeyi (ör. DB oturumu) otomatik verip iş bitince kapatması.

## 6. Docker ve docker-compose
**Dockerfile (multi-stage):**
1. `css` aşaması: uv ile dev bağımlılıkları kurar, `scripts/build_css.sh` → `app.css`.
2. `runtime` aşaması: `python:3.12-slim-bookworm`, uv binary'si sabit tag'li imajdan kopyalanır, `uv sync --locked --no-dev`, kod + `app.css` kopyalanır, **root olmayan kullanıcı**, `EXPOSE 8000`, `CMD` = `alembic upgrade head && fastapi run app/main.py --host 0.0.0.0 --port 8000`.
- WeasyPrint sistem kütüphaneleri (pango vb.) **M3'te** eklenir (açık soru 13).

**docker-compose.yml:**
- `db`: `postgres:16`, `POSTGRES_USER/PASSWORD/DB` `.env`'den, `pg_isready` healthcheck, `pgdata` volume.
- `app`: `build: .`, `env_file: .env`, `environment: DATABASE_URL=postgresql+psycopg://...@db:5432/unfurl` (lokaldeki SQLite URL'ini ezer), `depends_on: db: condition: service_healthy`, port `8000:8000`.
- `.dockerignore`: `.venv`, `.git`, `.env`, `*.db`, `docs/prototype`, cache'ler.

> 🎓 **Image / container:** Image, uygulamanın ve gereken her şeyin paketlenmiş hâli; container onun çalışan kopyası. **Multi-stage build:** Build araçlarını (Tailwind) ilk aşamada kullanıp son imaja sadece sonucu koyar → küçük ve güvenli imaj. **docker-compose:** Birden fazla container'ı (app + postgres) tek komutla birlikte başlatır. **Volume:** Container silinse de veritabanı verisinin kalmasını sağlar.

## 7. GitHub Actions (`.github/workflows/ci.yml`)
Tetik: tüm branch'lere `push` ve `main`'e `pull_request`.
- **Job `lint-test`** (ubuntu-latest): checkout → `setup-uv` (uv versiyonu sabit, cache açık) → `uv sync --locked` → `uv run ruff check .` → `uv run ruff format --check .` → `uv run pytest`. Testler CSS build'e ihtiyaç duymaz.
  - **Çift çalışmayı önleme:** `if: github.event_name == 'push' || github.event.pull_request.head.repo.full_name != github.repository`. Aynı repodaki bir branch'in PR'ında lint-test zaten push ile çalışmıştır ve sonucu aynı commit'e bağlı olduğu için PR'da yeşil tik olarak görünür; PR tetiklemesi sadece fork'tan gelen PR'larda çalışır.
- **Job `docker`**: `if: github.event_name == 'pull_request'` → sadece `main`'e açılan PR'larda. `cp .env.example .env` → `docker compose up -d --build --wait` → `curl -f http://localhost:8000/` → `docker compose down`. “Postgres üzerinde çalışıyor” kabul kriterini CI'da doğrular.
- `concurrency: { group: ci-${{ github.ref }}, cancel-in-progress: true }` → aynı branch'e art arda push'ta eski çalışma iptal olur.

> 🎓 **`if:` koşulu (Actions):** Bir job'un hangi olayda (push / pull_request) çalışacağını belirler. **concurrency:** Aynı gruptaki eski, artık gereksiz çalışmaları iptal eder.

> 🎓 **CI (Continuous Integration):** Her push'ta kodun temiz bir makinede otomatik test edilmesi; PR'daki yeşil tik bunun sonucudur. **ruff:** Hem hata/stil denetleyici (lint) hem formatlayıcı.

## 11. Riskler
1. **Tailwind v4 + pytailwindcss:** v4 CSS-tabanlı config kullanır; pytailwindcss'in v4 binary'sini indirdiği Build'in ilk adımında doğrulanır. Olmazsa v3 + `tailwind.config.js`'e dönülür (DECISIONS'a yazılır).
2. **Alpine ve CSP:** §10.1 “sadece kendi origin'inden script” istiyor. Standart Alpine `unsafe-eval` ister; M13'te CSP eklenince şablonların yeniden yazılması gerekebilir → açık soru 4.
3. **SQLite ↔ Postgres farkları:** Lokal SQLite, prod Postgres. Önlem: `render_as_batch`, naming convention, CI'da Postgres'li docker job.
4. **Platform farkı:** Mac ARM'de build edilen imaj, Render'da amd64. M13'te `--platform` ile ele alınır; M0'da sadece not.
5. **Tema kalıcılığı geçici:** Cookie → M4'te `User.theme`'e geçiş; giriş yapan kullanıcıda iki kaynağın önceliği M4'te belirlenmeli.
6. **Sistem Python'u 3.15:** Makinede 3.15 var; uv 3.12'yi kendisi indirir. README bunu belirtir.
7. **Docker Desktop çalışmıyorsa** compose hatası; README'de ön koşul olarak yazılır.
8. **Variable fontlar ve PDF:** Variable fontlar (özellikle Source Serif 4, Classic CV şablonu) M3'te WeasyPrint ile test edilecek; sorun çıkarsa PDF şablonları için statik woff2/ttf eklenir.
