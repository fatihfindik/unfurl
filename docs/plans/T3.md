# #3 — Pin Actions to SHA, images to digest · Teknik plan (Design fazı)

## Context
Issue #3 (`v1`, `tech-debt`), M0 güvenlik incelemesinden (bulgu #5, #6). Action'lar tag ile sabit (`actions/checkout@v7`, `astral-sh/setup-uv@v10.3.3`): bir tag başka koda taşınabilir. Docker image'ları da sadece tag ile (`python:3.12-slim-bookworm`, `ghcr.io/astral-sh/uv:0.13.7`, `postgres:16`): build birebir tekrarlanamaz. D-003'te "Action'ları commit SHA ile sabitlemek ileride değerlendirilebilir" notu var.

**Gündüz çalışması (2026-11-20):** Fatih dışarıdayken yapıldı; yetki: plan + kod + commit + push + PR, merge ve tag yok. Kararlar **"Claude karar verdi"**, Fatih'in onayını bekliyor. Branch `t3-pin-versions`.

### Kabul kriterleri
- `ci.yml`'deki her `uses:` tam commit SHA'sı + `# vX.Y.Z` yorumu.
- Dockerfile'daki python ve uv image'ları, compose'daki ve CI'daki `postgres:16` `@sha256:` digest'iyle (multi-arch index digest'i: Mac'te arm64, CI'da amd64 çalışır).
- `.github/dependabot.yml`: `github-actions`, `docker` (Dockerfile) ve `docker-compose` için haftalık güncelleme PR'ları.
- `docker compose build` ve CI (lint-test, postgres-tests, docker job'ları) yeşil.

## Kararlar
- **D-143 · Action'lar SHA'ya, image'lar digest'e (Claude karar verdi):**
  - Action'lar: `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1` (v7 şu an bu commit'te), `astral-sh/setup-uv@68559e99cc807c1eb7e9238fd43a15bba460eec2 # v10.3.3`. SHA'lar `gh api repos/<owner>/<repo>/git/ref/tags/<tag>` ile alındı.
  - Image'lar: `tag@sha256:…` (tag okunabilirlik için kalır, Docker digest'i kullanır). Digest'ler `docker buildx imagetools inspect` ile (index digest'i):
    - `python:3.12-slim-bookworm@sha256:935c3c5b12357a7e10caa9c1e6ca5692344d97cf229832ef584be2cec9fc03df`
    - `ghcr.io/astral-sh/uv:0.13.7@sha256:96f40d3904aad8d0bd010539001d36c8e2188b981e1334471a90c4a1d93bb490`
    - `postgres:16@sha256:3950ad7c3148ca2175ef1b6c36c9efbf78957ae8fbe8b3a5d7c35af50500382f`
  - Image'ların media type'ı `application/vnd.oci.image.index.v1+json` (multi-arch index, kontrol edildi).
  - Dockerfile'daki `ARG PYTHON_IMAGE` yerine adlı bir temel stage (`FROM python:…@sha256:… AS base`, sonra `FROM base AS css` / `AS runtime`): Dependabot `FROM` satırlarını günceller, ARG'yi güncellemez. Image tek yerde kalır. Stage adı `python` değil (image adıyla karışırdı).
  - Dependabot (`.github/dependabot.yml`): `github-actions` (`/`), `docker` (`/`, Dockerfile), `docker-compose` (`/`), haftalık, en fazla 5 açık PR, 7 gün `cooldown` (yeni bir sürüm bir hafta beklemeden önerilmez: kötü bir yayın genelde bu sürede fark edilir), commit mesajı `build(deps): …` (Conventional Commits, WORKFLOW §3). Action'lar tek PR'da gruplanır.
  - **SPEC §3 sürümleri bot PR'ıyla değişmez:** `python` için minor ve major, `postgres` için major güncellemeler `ignore`'da. Sadece digest yenilemeleri ve patch'ler gelir. Python 3.13 veya Postgres 17 bir SPEC değişikliğidir (Postgres major'ı mevcut `pgdata` volume'ünü de bozar), elle yapılır.
  - CI'daki `services.postgres.image`'ı ve `setup-uv`'nin `version: "0.13.7"`'sini Dependabot güncellemez. CI'ın `docker` job'ına bir adım: postgres image'ı (compose ↔ ci.yml) ve uv sürümü (Dockerfile ↔ ci.yml) aynı değilse başarısız olur (düz shell, bağımlılık yok). Böylece bir Dependabot PR'ı ci.yml güncellenmeden yeşil olmaz.
  - Python paketleri (`uv`) kapsam dışı: issue sadece Action'lar ve image'lar.
  - Yeni bağımlılık yok (Dependabot GitHub'ın servisi; projeye paket eklemiyor).
- **Alternatifler:** Tag'lerde kalmak (issue'nun riski); digest'i tag olmadan yazmak (hangi sürüm olduğu okunmaz); Renovate (ayrı bir GitHub App, daha fazla ayar).
